# Human authorization and exception review
Status: prototype; independent reviewer not assigned. No deployment workflow exists.
1. Open a same-repository PR targeting develop/enterprise-security-automation. Reference EXC-0001/0002 and original scan evidence. The PR author proposes exact scope, reason, compensating controls, reviewer login, approved_on (UTC review date), expires_on (within 90 days), status approved and approval_pr (this PR's number). These are proposed metadata, NOT approval.
2. An independently authorized reviewer inspects the complete diff and evidence, then uses GitHub Review changes > Approve or Request changes. Do not approve own PR. Review must match latest head SHA and proposed date; changes require new review.
3. CI verifies the reviewer against the authorization register, matches exact record to reviewed PR head, requires the latest decisive review to approve that head, and retains review identifiers with scanner and gate evidence. A pending record returns exit 2. Rejected or unverifiable approval fails verification. No automated merge or deployment.
4. Merge only after both required checks and human review succeed. Later CI revalidates merged PR evidence and expiration. Reopen review on material changes.
## Required manual repository configuration
Repository Settings > Rules > Rulesets: create active branch ruleset targeting develop/enterprise-security-automation. Require pull requests, one independent approval, dismiss stale approvals, require approval of most recent reviewable push, require baseline and review checks after they appear, block force pushes/deletion, and avoid bypass actors. Protect changes to workflows, security scripts, authorized-reviewers.json and exception policy with trusted independent review (CODEOWNERS once reviewer assigned). Restrict write access. Until configured, verification is not a tamper-resistant enforcement boundary. A personal repository with only one human cannot demonstrate independent approval; request a second trusted collaborator. Never fabricate identities or grant broad privileges for a demo.
## Evidence
review-evidence.json records authenticated review references (when approved); trivy.json retains raw findings; gate.json records evaluation. Artifacts retention 14 days; durable retention not implemented. Review rejection leaves request open or closed without merge. Reviewer allowlist is deliberately empty pending owner designation.
