# Human authorization and exception review
Current model: sole owner final authority, matthewkniskern-source. This is explicitly NOT independent review or separation of duties. No deployment workflow exists.
## Owner attestation
1. Open a same-repository PR targeting develop/enterprise-security-automation. Propose exact exception records, approved_by owner login, approval_pr, approved_on UTC date, expires_on within 90 days and status approved. These are proposals, not actual approval.
2. Owner personally inspects the full diff and evidence. GitHub does not permit formal self-approval of a PR. Instead the owner personally posts a new PR conversation comment for each exception, exactly: EXCEPTION EXC-0001 APPROVE <full PR head SHA> (replace ID and SHA as appropriate). To reject use EXCEPTION EXC-0001 REJECT <SHA>. Never use automated or assistant-posted comments as owner decisions; identity authenticity is limited by shared/account-delegated credentials.
3. Rerun the PR CI from Actions after commenting; comments do not automatically trigger this branch workflow. If the UTC date or commit changes, update proposal and attest again. Verification checks account, unedited comment, latest decision, exact head SHA, exact reviewed record and date. Pending or rejected approvals block. Merge manually only when checks pass. No cloud deployment authorized by this process.
4. For revocation, post a new rejection comment, revert approved status and rerun CI. Review expiry and changes before any future deployment.
## Future independent review
Set approval_mode to independent_review in a reviewed change and add trusted reviewer logins; current independent PR review verification rejects author self-approval. Conditional and secondary authorities are future extensions; no second authority configured today.
## Manual safeguards
Settings > Rules > Rulesets: target the development branch, require pull requests and passing baseline checks, block force pushes/deletion, restrict write access. Do not require formal independent approvals in the sole-owner model; that would deadlock. Switch to mandatory independent approvals when another reviewer is established. Protect policy and workflow changes. The owner retains final authority and can change configuration; this is not tamper-resistant segregation of duties. Automation uses the owner's delegated GitHub connection, so account identity alone cannot prove a human personally authored a comment. Owner must submit attestations directly in the UI; assistant must never submit them.
## Evidence
review-evidence.json records verified comment or review identifiers. Raw scanner reports and gate decisions are retained for 14 days. No deployment workflow exists.
